# HotNews 需求研究

> v0.2 · 2026-05-31 · 阶段：需求研究

---

## 1. 目标

| 类型 | 说明 |
|------|------|
| **产品** | 一屏浏览微博、知乎、B 站热榜，约 30 秒内扫完，点击跳转原文 |
| **学习** | 全栈练手：自建抓取 → 缓存 → API → 前端 → 部署 |
| **定位** | 个人热点仪表盘，非商业版「今日热榜」 |

**成功标准：** 三平台 Top 20 可见；数据延迟 ≤15 分钟；单平台失败不影响其余；首屏加载 <2s（缓存命中）。

**已确认决策：** 用户 = 个人刷热点；不依赖第三方热榜 API。

---

## 2. 调研发现

**需求成立：** [今日热榜](https://tophub.today/) 等成熟产品验证「跨平台热点聚合」真实存在；动机与「告别算法推荐、主动看榜」一致。

| 类别 | 发现 |
|------|------|
| **商业竞品** | 今日热榜（30+ 平台、历史/订阅）；rebang、AnyKnew 等偏轻量 UI |
| **开源参考** | [DailyHotApi](https://github.com/imsyy/DailyHotApi)、[DailyHot](https://github.com/imsyy/DailyHot)、[HotList-Web](https://github.com/uxiaohan/HotList-Web)、[TrendRadar](https://github.com/sansan0/TrendRadar) |
| **数据源** | 四平台均无稳定官方热搜 API；知乎/微博/B 站可抓，**抖音难度高** |
| **差异化** | 极简三平台、Top 20、数据自主、代码可学；不拼功能广度 |

---

## 3. 核心需求

### 3.1 功能（MVP）

- 首页三栏/三 Tab：微博、知乎、B 站各 **Top 20**（排名、标题、热度、外链）
- 后台 **每 10–15 分钟** 抓取并写入缓存；`GET /api/hot/:platform` 只读缓存
- 加载/错误态：骨架屏；单平台失败显示提示，其余正常
- 响应式 Web；展示最后更新时间；**无登录、搜索、收藏、历史**

### 3.2 非功能

- 统一数据模型：`{ rank, title, heat, url, platform }`
- 每平台独立 Adapter；仅展示摘要 + 外链，不镜像全文
- 抓取频率受控，个人学习用途

---

## 4. 风险与约束

| 风险/约束 | 影响 | 应对 |
|-----------|------|------|
| 反爬 / 接口变更 | 数据断供 | 分平台 Adapter；失败降级；降频抓取 |
| 服务条款与合规 | 法律风险 | 只存标题/排名/热度/链接 |
| 范围膨胀 | 无法交付 | 锁定 MVP：3 平台、Top 20、无账号 |
| 抖音抓取难 | 四平台愿景延后 | v1 三平台，抖音作二期 |
| 重复造轮子 | 投入质疑 | 目标明确为学习与自控，非商业对标 |
