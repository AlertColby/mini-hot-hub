## 1. 产品概述

### 1.1 产品简介

HotNews 是一个**个人热点聚合仪表盘**，一屏展示微博、知乎、B 站三大平台实时热榜 Top 20，约 30 秒内快速扫完当日热点，点击即可跳转原文。

### 1.2 产品定位

| 维度 | 说明 |
|------|------|
| **目标用户** | 个人用户（开发者本人），用于日常刷热点 |
| **核心价值** | 跨平台热点一站式浏览，告别算法推荐，主动看榜 |
| **产品类型** | Web 应用（响应式），全栈自建 |
| **非目标** | 不做商业版、不做用户系统、不做内容聚合平台 |

### 1.3 产品愿景

做一个**极简、自控、可学**的热点仪表盘——数据自主抓取，代码透明可维护，不依赖第三方热榜 API。

---

## 2. 产品目标与成功标准

### 2.1 业务目标

| 目标 | 描述 |
|------|------|
| **可用性** | 三平台 Top 20 始终可见 |
| **时效性** | 数据延迟 ≤ 15 分钟 |
| **健壮性** | 单平台抓取失败不影响其余平台展示 |
| **体验** | 首屏加载 < 2s（缓存命中时） |

### 2.2 成功指标

- 三平台热榜数据正常展示，无空白页
- 后台抓取任务稳定运行，数据每 10–15 分钟刷新
- 任一平台接口异常时，该平台显示降级提示，其余平台不受影响
- 页面从打开到内容可见 ≤ 2 秒

## 3. 用户需求

### 3.1 用户场景

作为一名信息消费者，我希望：

1. **快速扫榜** — 打开一个页面就能同时看到微博、知乎、B 站的热搜/热榜，不用分别打开三个 App 或网站。
2. **点击跳转** — 看到感兴趣的热点，点击标题直接跳转到原文查看详情。
3. **感知热度** — 每条热点都有排名和热度数值，能直观判断话题热度。
4. **知道时效** — 清楚数据更新时间，判断信息新鲜度。
5. **多端可用** — 手机、电脑都能方便地浏览。

### 3.2 用户故事

| ID | 用户故事 | 优先级 |
|----|---------|--------|
| US-01 | 作为用户，我打开首页就能看到微博、知乎、B 站三个平台的热榜 | P0 |
| US-02 | 作为用户，每个平台展示 Top 20，包含排名、标题、热度值 | P0 |
| US-03 | 作为用户，点击热榜条目能跳转到对应平台的原文页面 | P0 |
| US-04 | 作为用户，我能看到每个平台数据的最后更新时间 | P1 |
| US-05 | 作为用户，数据加载时看到骨架屏/加载状态，而非空白页 | P1 |
| US-06 | 作为用户，某平台抓取失败时能看到提示，其他平台正常展示 | P1 |
| US-07 | 作为用户，在手机和电脑上都能正常浏览 | P1 |

## 4. 功能需求

### 4.1 MVP 功能清单

| ID | 功能 | 描述 | 优先级 |
|----|------|------|--------|
| F-01 | 多平台热榜展示 | 首页同时展示微博、知乎、B 站热榜 | P0 |
| F-02 | Top 20 列表 | 每平台展示前 20 条热点 | P0 |
| F-03 | 热度与排名 | 每条热点显示排名序号、热度数值 | P0 |
| F-04 | 外链跳转 | 点击标题在新标签页打开原文 | P0 |
| F-05 | 后台定时抓取 | 每 10–15 分钟自动抓取并写入缓存 | P0 |
| F-06 | 缓存 API | `GET /api/hot/:platform` 只读缓存数据 | P0 |
| F-07 | 展示最后更新时间 | 页面显示各平台数据的抓取时间 | P1 |
| F-08 | 骨架屏加载态 | 数据加载时展示骨架屏 | P1 |
| F-09 | 单平台失败降级 | 单平台异常时显示错误提示，其余正常 | P1 |
| F-10 | 响应式布局 | 桌面端三栏，移动端 Tab 切换或堆叠 | P1 |

### 4.2 显式不做（MVP 阶段排除）

- 用户登录/注册/账号系统
- 搜索功能
- 收藏/书签
- 历史记录/趋势图
- 抖音热榜（抓取难度高，列入二期）
- 推送/通知
- 评论/互动
- 内容全文镜像

### 4.3 页面结构

```
首页
├── Header（Logo + 最后更新时间）
├── 平台热榜区域（三栏或三 Tab）
│   ├── 微博热搜榜（Top 20）
│   ├── 知乎热榜（Top 20）
│   └── B 站热搜榜（Top 20）
└── Footer（版权/技术栈信息）
```

### 4.4 数据模型

统一数据模型，所有平台适配到此结构：

```typescript
interface HotItem {
  rank: number;       // 排名 (1–20)
  title: string;      // 标题
  heat: string;       // 热度（格式化字符串，如 "95.6万"）
  url: string;        // 原文链接
  platform: string;   // 平台标识: "weibo" | "zhihu" | "bilibili"
}

interface HotList {
  platform: string;       // 平台标识
  items: HotItem[];       // 热点列表
  updatedAt: string;      // 抓取时间 ISO 8601
  error?: string;         // 抓取失败时的错误信息
}
```

### 4.5 API 设计

| 端点 | 方法 | 描述 | 响应 |
|------|------|------|------|
| `/api/hot/:platform` | GET | 获取指定平台热榜 | `HotList` |
| `/api/hot` | GET | 获取所有平台热榜 | `HotList[]` |
| `/api/health` | GET | 健康检查 | `{ status: "ok", updatedAt: string }` |

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标值 | 备注 |
|------|--------|------|
| 首屏加载时间 | < 2s | 缓存命中时 |
| API 响应时间 | < 100ms | 读取缓存 |
| 抓取任务耗时 | < 30s/平台 | 含网络请求与解析 |
| 并发支持 | ≥ 10 并发请求 | 个人使用，低并发要求 |

### 5.2 可靠性

- **单平台隔离**：每个平台独立 Adapter，单一平台失败不影响其他平台
- **失败降级**：抓取失败时返回缓存中的旧数据 + error 字段，不返回空列表
- **优雅关闭**：进程退出时等待进行中的抓取完成（最长 30s）

### 5.3 可维护性

- **Adapter 模式**：每平台独立 Adapter 模块，新增平台只需实现接口
- **统一数据模型**：所有 Adapter 输出统一 `HotItem[]` 结构
- **日志记录**：抓取成功/失败均记录日志，便于排查

### 5.4 安全与合规

| 约束 | 应对 |
|------|------|
| 反爬 / 接口变更 | 分平台 Adapter 独立维护；降频抓取；User-Agent 模拟正常浏览器 |
| 服务条款合规 | 仅存储标题、排名、热度、链接，不镜像正文/图片 |
| 数据使用 | 个人学习用途，不上传/分享数据 |

## 6. 数据源

### 6.1 支持平台

| 平台 | 标识 | 数据来源 | 抓取方式 | 难度 |
|------|------|---------|---------|------|
| 微博 | `weibo` | 微博热搜榜页面 | HTTP 抓取 + HTML 解析 | 中 |
| 知乎 | `zhihu` | 知乎热榜页面 | HTTP 抓取 + HTML/API 解析 | 中 |
| B 站 | `bilibili` | B 站热搜 API | HTTP 请求 + JSON 解析 | 低 |

### 6.2 抓取策略

- **频率**：每 10–15 分钟一轮
- **并发**：三轮同时发起（不串行等待）
- **重试**：失败后本轮不重试，等下一轮
- **缓存**：成功抓取后写入内存/文件缓存；API 只读缓存

## 8. 风险与约束

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| 反爬机制升级 | 数据断供 | 中 | 分平台 Adapter 独立维护；模拟正常请求；降频 |
| 页面结构变更 | Adapter 失效 | 中 | 日志监控；独立 Adapter 便于快速修复 |
| 抖音抓取困难 | 无法扩展四平台 | 高 | v1 明确三平台；抖音列入 v2 研究 |
| 范围膨胀 | 无法交付 | 中 | 严格锁定 MVP 范围，拒绝功能蔓延 |
| 重复造轮子质疑 | 投入产出存疑 | 低 | 明确定位为学习与自控，非商业对标 |

## 9. 版本规划

### v1.0 — MVP（当前）

- 三平台热榜展示（微博、知乎、B 站）
- Top 20 列表 + 热度 + 外链
- 后台定时抓取 + 缓存 API

- PWA 支持

## 10. 技术栈

> 详细技术方案见后续 `ARCHITECTURE.md`。

| 层次 | 技术选型 | 说明 |
|------|---------|------|
| **前端** | React + TypeScript + Vite + CSS | SPA 响应式布局；Vite 开发/构建 |
| **后端** | Node.js + Express | HTTP Server + 定时抓取任务 |
| **缓存** | 内存缓存（Node 进程内） | MVP 阶段直接内存缓存，无需 Redis |
| **抓取** | axios + cheerio | HTTP 请求 + HTML 解析；JSON API 直接解析 |
| **部署** | 前端 Vercel / 后端 Railway | 示例方案，不强制统一；也可单机 Docker |
